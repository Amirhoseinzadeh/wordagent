# تست و کنترل کیفیت

## اجرا

```bash
flutter test                      # همه‌ی تست‌ها
flutter test test/domain          # فقط موتورهای دامنه
flutter test test/utils/fa_format_test.dart
flutter analyze
```

از آن‌جا که همه‌ی موتورهای آموزشی **تابع خالص** هستند و زمان از `AppClock`
(و در تست‌ها از یک ساعت ثابت) عبور می‌کند، هیچ تستی به شبکه، پلتفرم یا
ساعت واقعی وابسته نیست.

## یکپارچگی مداوم (CI)

گردش‌کار `.github/workflows/ci.yml` روی هر push و Pull Request این زنجیره را
اجرا می‌کند: `flutter pub get` → `flutter analyze` (فقط خطاها بازدارنده‌اند) →
`flutter test --timeout 60s` → `flutter build web --release`. مرحله‌ی آخر مهم
است: تضمین می‌کند همه‌ی لایه‌ها روی یک پلتفرم واقعی (وب) هم کامپایل می‌شوند.

هر مرحله مستقل، با سقف زمانی و `continue-on-error` اجرا می‌شود تا یک توقف
(مثلاً تست بی‌پایان) بقیه‌ی بازخورد را از بین نبرد؛ وضعیت هر مرحله در فایل
`*.status` می‌ماند و گام آخر بر پایه‌ی همان‌ها موفق/ناموفق را تعیین می‌کند.

خروجی analyze و test و build به‌صورت خودکار در یک **کامنت روی همان کامیت**
منتشر می‌شود (شامل فهرست تست‌های شکست‌خورده و جزئیات `Expected/Actual`). این
کار برای محیط‌هایی است که خواندن لاگ‌های Actions در آن‌ها ممکن نیست:

```bash
gh api /repos/<owner>/<repo>/commits/<sha>/comments --jq '.[0].body'
```

## تحلیل ایستای سبک (بدون SDK)

در محیط‌هایی که Flutter نصب نیست، چهار ابزار مستقل در `tools/dev/` کار تحلیل
ایستا را تا حد ممکن پوشش می‌دهند:

```bash
node tools/dev/dartcheck.mjs .          # نحو، توازن بلوک، خطای ایمپورت (tree-sitter)
python3 tools/dev/member_check.py .     # عضو ناشناخته‌ی کلاس/enum + کامل بودن switch روی enum
python3 tools/dev/arg_check.py .        # آرگومان نام‌دار/جایگاهی نادرست در سازنده‌ها و توابع
python3 tools/dev/import_check.py .     # نام‌هایی که از ایمپورت‌ها دیده نمی‌شوند
```

خروجی هر ابزار با یک عدد خلاصه تمام می‌شود؛ عدد `problems: 0` یعنی چیزی پیدا
نشده. این ابزارها **جای `flutter analyze` را نمی‌گیرند**؛ شبکه‌ی ایمنی سریع
برای وقتی‌اند که SDK در دسترس نیست. نمونه‌ی واقعی: `member_check.py` یک خطای
کامپایل واقعی (`AchievementMetric.sessionsDone` که در enum وجود نداشت) را
پیش از اجرای CI پیدا کرد.

> هر چهار ابزار روی همین مخزن صفر ایراد گزارش می‌کنند؛ اگر عددی جز صفر دیدید،
> اول به کد مشکوک شوید و بعد به ابزار.

## تصویر واژه

صفحه‌ی جزئیات هر واژه یک «کارت تصویر» دارد (`lib/widgets/word_image.dart`).
منبع تصویر به‌ترتیب اولویت: دارایی محلی `assets/images/<id>.{webp,png,jpg,jpeg}`
که `tools/build_content.py` آن را در کلید `image` می‌گذارد، و در نبودش تصویر
آنلاین `image_url`. اگر هیچ‌کدام نبود، کارت جایگزین فارسی («تصویر این واژه
به‌زودی») با واترمارک حرف اول واژه نمایش داده می‌شود — یعنی گرافیک ناقص
هرگز به کاربر نشان داده نمی‌شود.

## نکته‌های تست‌نویسی در این پروژه

- **زمان:** هرگز `DateTime.now()` در تست‌ها استفاده نمی‌شود؛ همه‌جا `testNow`
  یا `AppClock(provider: …)` تزریق می‌شود.
- **محتوا:** تست محتوا فایل‌های واقعی `assets/content` را (با mock کردن باندل
  دارایی‌ها) می‌خواند؛ بنابراین اگر واژه‌ای معنی فارسی نداشته باشد، تست می‌شکند.
- **بدون شبکه:** سرویس صوتی در تست‌ها با `FakeAudioService` جایگزین می‌شود و
  ذخیره‌سازی با `MemoryLocalStore` انجام می‌گیرد.
- **رفتار، نه پیاده‌سازی:** تست‌ها به جزئیات داخلی موتورها وابسته نیستند؛
  ورودی/خروجی و قوانین آموزشی سنجیده می‌شود.

## یافته‌های تست که به اصلاح کد انجامید

این‌ها نشان می‌دهد تست‌ها واقعاً کار می‌کنند و نه فقط پوشش صوری:

1. `WordRepositoryImpl` پس از به‌روزرسانی آنلاین، محتوای تازه را اعمال
   **نمی‌کرد** (نسخه‌ی بسته دوباره بار می‌شد) → حالا نسخه‌ی محلی اولویت دارد.
2. لرزش تصادفی بازه‌ی مرور **بعد از** محدودسازی اعمال می‌شد و می‌توانست
   فاصله را از سقف یک‌ساله عبور دهد → ترتیب اصلاح شد.
3. `FaFormat.compactNumber` برای اعداد گرد اعشار بی‌معنی می‌داد
   (`۱۲٫۰ هزار`) → اعداد گرد بدون اعشار نمایش داده می‌شوند.
4. `TextNormalizer.stripEndPunctuation` نشانه‌ی پرسشی فارسی «؟» را پاک
   نمی‌کرد → پشتیبانی از «؟» و «…» اضافه شد.
5. `AchievementMetric.sessionsDone` در `labels.dart` استفاده شده بود اما در enum
   وجود نداشت (خطای کامپایل) → این عضو حذف شد.
6. `AppRouter.build` در `app.dart` سیزده بار با آرگومان جایگاهی صدا زده می‌شد
   در حالی که `builder` نام‌دار است → همه‌ی فراخوانی‌ها اصلاح شد.
7. `TagChip` در پنج فایل استفاده شده بود بدون ایمپورت کتابخانه‌اش
   (`widgets/app_button.dart`) → ایمپورت‌ها اضافه و ایمپورت‌های بی‌استفاده حذف شدند.
8. `ReviewState.isActive` وجود نداشت در حالی که صفحه‌ی بسته و تست‌ها از آن
   استفاده می‌کردند → این getter اضافه شد.
9. نتیجه‌ی تعیین سطح، امتیاز را نمایش می‌داد اما به کیف XP کاربر اضافه نمی‌کرد
   → پارامتر `creditSessionXp` در `finishSession` اضافه شد.
10. `challengesDone` از زنجیره‌ی چالش روز جاری ساخته می‌شد (عدد نادرست برای
    دستاوردها) → از تاریخچه‌ی واقعی جلسه‌های چالش شمرده می‌شود.
11. تست ویجت راه‌اندازی اپ در ناحیه‌ی زمان جعلی روی I/O واقعی گیر می‌کرد و
    بعد از ۱۰ دقیقه timeout می‌داد → بارگذاری محتوا با `tester.runAsync`
    انجام می‌شود.
12. `TextNormalizer.normalizeFa` حرف «ى» عربی (الف مقصوره) را نمی‌شناخت و پاسخ
    درست کاربر غلط شمرده می‌شد → به فهرست نرمال‌سازی اضافه شد.
